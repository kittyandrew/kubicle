# Development

## Gates

Run these before presenting work as done. Heavy commands take one of three build slots and a memory cap, so at
most three run at once (the desktop has been OOM-killed by uncapped parallel builds). Measured: a cargo check or
clippy peaks at a few GB, a Nix client at about 1.3 GB; the cap only bounds what runs in our scope, and Nix
builds, VM tests included, run in the daemon outside it.

VM tests take `vm`, never `b`: a VM run holds its lock for many minutes while it mostly waits, and would starve
compiles. Two VM runs at once, since each check takes 1-3 GB per VM and the desktop has 30 GB.

```bash
pool() { # pool <lock prefix> <slots> <command...>
  local prefix=$1 slots=$2; shift 2
  while :; do
    for slot in $(seq "$slots"); do # -E 75: "slot busy", told apart from the command's own exit code
      flock -n -E 75 "/tmp/$prefix.$slot.lock" systemd-run --user --scope -q -p MemoryMax=6G -p MemorySwapMax=0 "$@"
      rc=$?; [ "$rc" -ne 75 ] && return "$rc"
    done
    sleep 2
  done
}
b() { pool kubicle-build 3 "$@"; }
vm() { pool kubicle-vm 2 "$@"; }
nix develop .#lint -c tests/lint.sh # every formatter, linter and type checker, as CI runs them
b nix develop -c cargo clippy --workspace --exclude kubicle-web -- -D warnings
b nix develop -c cargo clippy -p kubicle-web --target wasm32-unknown-unknown -- -D warnings
tests/suite.sh   # every flake check but vm-settings, about 14 minutes; `tests/suite.sh vm-full` runs one
```

`tests/suite.sh` runs the VM tests' drivers itself, side by side in one memory-capped slice, longest first while
their measured peaks fit, and judges them as the flake checks do; the suites test the `fast` Cargo profile, which
rebuilds in seconds. Read its header before changing a VM test's size. CI (`.github/workflows/quality.yml`) runs
`tests/lint.sh` alone, nothing that compiles, so a new gate goes in that script; `tests/suite.sh` runs it too.
Runs are serial across the machine: a second `tests/suite.sh`, from any checkout, waits on its lock
(`/tmp/kubicle-suite.lock`) and says so. Just run it; never start VM drivers around it. Keep `KUBICLE_SUITE_DIR`
short (`/tmp/k...`): under a scratchpad the VMs' network socket path passes Unix's 108 characters and it hangs.

Flakes see only files in git's index: `git add` a new file before any `nix` command, or it does not exist.

## Tests

There are no unit tests (`docs/design.md`, Testing). Every suite is one flake check and runs the real program
against a real mail server, a real browser or real hostile input; the speed budgets alone run on the development
machine (`tests/budgets/run.sh`), as a VM is too slow to measure them. Put a new check in the cheapest suite where
the bug it guards against can make it fail.

- **Only checks that can fail stay.** When adding one, plant the bug it guards against and show it fails, then
  passes without the bug. A check no planted bug can fail is deleted.
- **A failed VM check is read, not rerun.** Its evidence is in the store (`docs/design.md`, Testing): `nix build
  .#checks.x86_64-linux.<check>.run --print-out-paths`, then the machine's journal, network log and screenshots. A
  new VM suite records through `tests/record.py` and is judged by `tests/judge.nix`.
- **Corpora are fetched by hash** (fixed-output derivations) at test time and never committed.
- **The dev mail server** for working by hand is the Dovecot fixture in `tests/fixture/`; its seeded mailboxes
  are the same ones the VM tests use.

## Style

- Rust: `rustfmt.toml` (141 columns), clippy pedantic (workspace `Cargo.toml`). rustfmt only reflows, so write a body
  as one statement where that reads as plainly, which `fn_single_line` keeps on one line. Nix: alejandra; TOML: taplo;
  Python: ruff, mypy; JS, TS, YAML: prettier, oxlint; shell: shellcheck. Prose comments wrap at about 110 columns.
- A VM test part skips undefined names in `ruff.toml`, never by `# ruff: noqa`, which covers the driver's whole script.
- Imports: one `use` per root (std, each external crate, `crate`), one filled line each. Deeper paths are written
  out inside its braces (`use jiff::{Timestamp, tz::TimeZone};`), never as an inner `{...}` group, which rustfmt
  always breaks over lines. A list past 139 columns, where rustfmt wraps a `use`, goes on in a second `use` of the
  same root, braced with two items at least: rustfmt sorts a one-item `use` above the braced ones. Groups std,
  external crates, `crate`, separated by a blank line. No rustfmt setting does this.
- Parse once, at the boundary: the HTTP edge or the IMAP decode turns input into types that cannot hold a bad
  value, and inner layers take those types and never re-check, re-parse or re-normalize them. A message is parsed
  once per request and passed on. Keep a second check only at a real trust boundary, and say so where it stands.
- One type per concept, used directly by every layer (kubicle-api's types reach the IMAP encoder): no twin enums or
  structs with a `From` between them; convert only where the two sides differ (imap-types' wire values), saying how.
- No `unwrap()` or `expect()` on anything that comes from the network, the mail or the user: return an error.
  `expect()` is for invariants of our own code, with the invariant as its message.
- Comments follow the global comment rules: explain what the code cannot, inline on the line they explain,
  no tombstones or history. Tag only a gotcha `@NOTE:`, a hazard `@WARNING:` or an action `@TODO:`, dated.
- `docs/design.md` and the README change in the same commit as the behaviour they describe, and so does the README
  badge's line count with any Rust change: `tokei crates -t Rust -C`, its code column, to the nearest hundred.

## Roundcube parity

kubicle rebuilds Roundcube's behaviour (`docs/design.md`, Features); only the exceptions listed there differ.
Before building or changing any user-facing feature, read how Roundcube does it, at the version in Mailu's
pinned webmail image (`git clone -b 1.6.18 https://github.com/roundcube/roundcubemail`, which has the same
source): `skins/elastic/templates/` for what exists, `program/js/app.js` for each command's behaviour,
`program/actions/` for the server side. Then rebuild it whole; a part left out needs Andrew's OK and a line in
design.md's exceptions.

## Secrets

Mailu tokens and passwords never reach a log, a file or the transcript; report only their presence or
length. Test fixtures use made-up accounts and passwords, which are not secrets.

## Dependencies

- `cargo update` refreshes `Cargo.lock`, which Nix reads directly; `nix flake update` the toolchain and nixpkgs.
  `wasm-bindgen` is pinned to the exact version of nixpkgs' `wasm-bindgen-cli`: bump both together.
- imap-codec is an alpha, pinned with `=` in `crates/kubicle-imap/Cargo.toml`: read its changelog before
  moving the pin, since alpha APIs change between releases.
